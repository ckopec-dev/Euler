# Euler Problem 474 Solution in Ada

I'll solve Euler Problem 474, which asks for the number of ways to write a positive integer n as a sum of positive integers, where each summand is at least 2 and at most 10.

## Problem Understanding

We need to find the number of partitions of a positive integer n into parts where each part is between 2 and 10 (inclusive). This is a classic dynamic programming problem.

## Solution Approach

I'll use dynamic programming with memoization. Let `dp[n][last]` represent the number of ways to partition n using parts no larger than `last`. However, since we want parts between 2 and 10, I'll adjust accordingly.

## Ada Implementation

```ada
with Ada.Text_IO; use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;

procedure Euler_474 is
   
   -- Maximum value for n (from problem statement)
   MAX_N : constant := 1000000;
   
   -- Array to store results
   DP : array (0 .. MAX_N) of Long_Long_Integer := (others => 0);
   
   -- Number of parts allowed (2 to 10)
   MIN_PART : constant := 2;
   MAX_PART : constant := 10;
   
begin
   -- Base case: there's one way to partition 0 (empty partition)
   DP(0) := 1;
   
   -- For each possible part size from 2 to 10
   for Part_Size in MIN_PART .. MAX_PART loop
      -- Update DP array for all values from Part_Size to MAX_N
      for N in Part_Size .. MAX_N loop
         DP(N) := DP(N) + DP(N - Part_Size);
      end loop;
   end loop;
   
   -- Output the result for n = 1000000
   Put("Answer: ");
   Put(DP(MAX_N), Width => 0);
   New_Line;
   
end Euler_474;
```

## Explanation

The solution uses a dynamic programming approach:

1. **Initialization**: Create an array `DP` where `DP[i]` represents the number of ways to partition integer `i`
2. **Base case**: `DP[0] = 1` (one way to make 0: use no parts)
3. **Fill DP table**: For each part size from 2 to 10, update all possible sums
4. **Transition**: For each part size `p`, and for each sum `n ≥ p`:
   - `DP[n] = DP[n] + DP[n-p]`
5. **Result**: `DP[MAX_N]` gives us the answer

## Optimization Notes

This implementation uses a space-optimized approach where we process parts in order, so we don't need to store intermediate results for different part sizes separately.

## Time and Space Complexity

- **Time Complexity**: O(n × k) where n = 1000000 and k = 9 (parts from 2 to 10)
- **Space Complexity**: O(n) for the DP array
