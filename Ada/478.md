# Euler Problem 478 Solution in Ada

I'll solve Euler Problem 478, which asks for the number of ways to write a positive integer n as a sum of distinct positive integers, where each integer is at least twice the previous one.

## Problem Analysis

The problem requires finding the number of partitions of n into distinct parts where each part is at least twice the previous part. This is equivalent to finding the number of ways to represent n as:
n = a₁ + a₂ + ... + aₖ
where a₁ < a₂ < ... < aₖ and aᵢ₊₁ ≥ 2×aᵢ

## Ada Solution

```ada
with Ada.Text_IO; use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;

procedure Euler_478 is
   
   -- Memoization array for dynamic programming
   type Memo_Array is array (0 .. 1000000) of Integer;
   Memo : Memo_Array := (others => -1);
   
   -- Function to count partitions with the given constraint
   function Count_Partitions(N, Min : Integer) return Integer is
      Result : Integer := 0;
   begin
      -- Base cases
      if N = 0 then
         return 1;
      elsif N < 0 or Min > N then
         return 0;
      end if;
      
      -- Check memoization
      if Memo(N) /= -1 then
         return Memo(N);
      end if;
      
      -- Try all possible next values
      for Next := Min .. N loop
         -- The next value must be at least twice the current minimum
         if Next >= Min then
            Result := Result + Count_Partitions(N - Next, Next * 2);
         end if;
      end loop;
      
      -- Store result in memoization table
      Memo(N) := Result;
      return Result;
   end Count_Partitions;
   
   -- Alternative approach using more efficient recursion
   function Solve(N : Integer) return Integer is
      function DP(Num, Prev : Integer) return Integer is
         Result : Integer := 0;
         Next : Integer;
      begin
         if Num = 0 then
            return 1;
         elsif Num < 0 or Prev > Num then
            return 0;
         end if;
         
         -- Generate all valid next numbers
         Next := Prev;
         while Next <= Num loop
            Result := Result + DP(Num - Next, Next * 2);
            Next := Next + 1;
         end loop;
         
         return Result;
      end DP;
   begin
      return DP(N, 1);
   end Solve;
   
   -- Optimized version with better memoization
   function Count_Ways(N : Integer) return Integer is
      type DP_Table is array (0 .. 1000000, 0 .. 1000) of Integer;
      Table : DP_Table := (others => (others => -1));
      
      function Recurse(Num, Min : Integer) return Integer is
      begin
         if Num = 0 then
            return 1;
         elsif Num < 0 or Min > Num then
            return 0;
         end if;
         
         if Table(Num, Min) /= -1 then
            return Table(Num, Min);
         end if;
         
         -- We can use the minimum value or larger values
         declare
            Result : Integer := 0;
            Next : Integer := Min;
         begin
            while Next <= Num loop
               Result := Result + Recurse(Num - Next, Next * 2);
               Next := Next + 1;
            end loop;
            
            Table(Num, Min) := Result;
            return Result;
         end;
      end Recurse;
   begin
      return Recurse(N, 1);
   end Count_Ways;
   
begin
   -- Print result for the specific problem (n = 10^6)
   Put("The answer to Euler Problem 478 is: ");
   Put(Count_Ways(1000000));
   New_Line;
   
end Euler_478;
```

## Explanation

This solution uses dynamic programming with memoization to efficiently count the partitions. Here's how it works:

1. **Recursive Approach**: The function `Count_Partitions` recursively explores all valid combinations where each element is at least twice the previous one.

2. **Memoization**: To avoid recomputing subproblems, we store results in a memoization table (`Memo` array).

3. **Constraint Handling**: The constraint that each part must be at least twice the previous one is enforced by passing `Next * 2` as the minimum value for the next recursion.

4. **Base Cases**: 
   - If N = 0, we have found one valid partition
   - If N < 0 or Min > N, there's no valid partition

## Key Optimizations

1. **Memoization**: Avoids recalculating the same subproblems
2. **Constraint Enforcement**: The `Next * 2` ensures the required inequality constraint
3. **Efficient Iteration**: Only iterate up to the current sum limit

## Time and Space Complexity

- **Time Complexity**: O(n²) in the worst case, but significantly better with memoization
- **Space Complexity**: O(n²) for the memoization table

The solution handles large numbers efficiently by using dynamic programming and avoiding redundant calculations through memoization.
